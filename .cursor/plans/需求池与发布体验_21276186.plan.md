# 需求池与发布体验重做

## 目标
- 需求池整卡可点击进入详情，移除“查看详情”，并复用工作台卡片的上浮/阴影反馈。
- 卡片操作顺序固定为“我也想用”紧跟需求方，“我来做”紧跟负责人；两个操作按钮使用圆形图标按钮并保留文字 Tooltip。
- 发布需求只要求标题、需求详情；详情支持插入图片，附件可选。
- 新增项目沟通/追加需求时间线，不覆盖原始需求，保留谁在什么时候补充了什么。
- 个人资料页只保留摘要信息；头像设置和修改密码通过明确按钮弹窗完成。
- 将当前 aiManager 工程作为一条幂等的真实案例需求写入当前开发数据库，并提供可复现的案例种子入口。

## 实施范围

### 1. 需求池卡片与工作台视觉
- 修改 [apps/web/app/projects/page.tsx](apps/web/app/projects/page.tsx)：移除详情链接；卡片主体增加键盘可访问的整卡跳转；按钮点击阻止冒泡，避免操作按钮触发详情跳转；调整需求方/负责人区域与操作按钮的顺序。
- 修改 [apps/web/app/globals.css](apps/web/app/globals.css)：新增可点击卡片的 hover/focus 上浮效果，复用 `.stat-card-link .ant-card` 的过渡、阴影和 `translateY` 规则；新增圆形操作按钮样式。
- 必要时抽出共享卡片交互样式，避免需求池和工作台出现两套 hover 行为。

### 2. 简化发布需求
- 修改 [apps/web/app/projects/new/page.tsx](apps/web/app/projects/new/page.tsx)：把六步向导收敛为标题 + 需求详情两个必填项，支持 Markdown/图片插入；附件组件保留为可选项；标签、技能、期望时间、验收条件等改为发布后在详情页补充。
- 新增可复用的需求详情编辑器组件，图片上传后把 Markdown 图片引用插入正文，并继续复用现有附件上传接口。
- 修改 [apps/api/src/projects/dto/projects.dto.ts](apps/api/src/projects/dto/projects.dto.ts) 与 [apps/api/src/projects/projects.service.ts](apps/api/src/projects/projects.service.ts)：放宽创建接口对验收、标签、技能等字段的依赖，保留标题和详情的基础校验；创建后仍正确挂载图片和附件。
- 调整 [apps/web/components/AttachmentUploader.tsx](apps/web/components/AttachmentUploader.tsx)、上传配置与 `.env.example`：格式不做白名单，大小改为环境变量可配置，默认 100MB；保留流式落盘、随机文件名和上传目录隔离，避免无限内存上传。

### 3. 沟通记录与追加需求
- 在 [apps/api/prisma/schema.prisma](apps/api/prisma/schema.prisma) 新增 `ProjectUpdate` 与 `ProjectUpdateKind`（沟通记录、追加需求），关联项目和用户；生成 Prisma migration。
- 新增项目更新 DTO，并在 [apps/api/src/projects/projects.controller.ts](apps/api/src/projects/projects.controller.ts) 和 [apps/api/src/projects/projects.service.ts](apps/api/src/projects/projects.service.ts) 增加列表/新增接口。
- 权限默认允许需求方、共同需求人、负责人、协作者和管理员发布记录；每条记录保留作者、时间、类型和正文。追加需求不改写原始描述，单独显示为变更记录。
- 新增通知：追加需求通知负责人，负责人回复/沟通通知需求方；复用站内通知体系，不强制同步为 Gitea Issue。
- 修改 [apps/web/app/projects/[id]/page.tsx](apps/web/app/projects/[id]/page.tsx)：详情页增加“沟通与追加需求”区域/页签，支持快速发表沟通记录或追加需求，并展示时间线；原有缺陷反馈继续保留为独立闭环。

### 4. aiManager 真实案例
- 新增幂等案例种子脚本（不清空现有演示数据），创建一条“内部需求协作平台”真实需求，内容覆盖当前项目的需求池、认领开发、Gitea 协作、成果中心和反馈闭环。
- 将脚本接入 [apps/api/package.json](apps/api/package.json) 或根目录脚本，并在当前开发数据库执行一次；案例使用当前管理员作为需求方，避免重复创建。
- 案例详情使用同一套图片插入、附件、沟通记录和追加需求能力，作为后续验收样本。

### 5. 个人资料页简化
- 修改 [apps/web/app/profile/page.tsx](apps/web/app/profile/page.tsx)：移除页面内展开的头像选择、资料编辑和密码表单，保留姓名、部门、邮箱、角色、Git 账号和热力图摘要。
- 头像区域改为点击当前头像打开设置弹窗，弹窗内保留头像选择、清除头像和保存操作；头像更新后刷新全局用户信息。
- “修改密码”改为账号信息区域中的按钮，点击打开独立弹窗，继续复用现有 `PUT /auth/password` 接口和校验逻辑。
- 保持移动端布局简洁，避免资料页首屏同时出现多组编辑控件。

## 验证
- API 单测覆盖：创建最小需求、附件挂载、项目更新权限、追加需求与沟通记录通知、案例幂等执行。
- Web 类型检查与构建；重点检查整卡点击、按钮阻止冒泡、键盘操作、图片插入和附件上传。
- 执行 Prisma migration、案例种子和 Docker/HTTP smoke test。
- 通过浏览器回归：需求池卡片跳转、两个圆形操作按钮、最小发布、插图/附件、沟通记录、追加需求、真实案例详情，以及资料页头像/密码弹窗。
